# Support

Use GitHub issues for reproducible module defects, documentation defects, and tenant-verification work that can be discussed without protected information.

Before opening an issue:

1. Confirm the PowerShell version with `$PSVersionTable`.
2. Record the module commit or release.
3. Reproduce the problem with synthetic or sanitized input when possible.
4. Remove tenant names, account identifiers, personal data, tokens, and secrets.
5. State whether the behavior is documented, observed, inferred, or still `VERIFY IN TENANT`.

Security matters belong in a private advisory, not a public support issue. See `SECURITY.md`.

The project does not provide emergency incident-response service through GitHub issues. During an active incident, follow the affected organization's approved response process while preserving evidence needed to reproduce any module defect later.
